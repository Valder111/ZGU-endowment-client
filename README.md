# Эндаумент-фонд ЗГУ

Статический сайт Заполярного государственного университета имени Н. М. Федоровского. Переработан из HTML/CSS/JavaScript в React + TypeScript с сохранением исходного дизайна, текстов и всех 44 адресов.

## Стек

- React 19 и TypeScript в строгом режиме.
- Vite с `@vitejs/plugin-react-swc`.
- Tailwind CSS 4 через `@tailwindcss/vite`.
- shadcn/ui: локальные компоненты, `components.json`, генератор `npm run ui:add -- <component>`.
- GSAP и ScrollTrigger как npm-зависимости с очисткой эффектов в React.
- ESLint, Prettier, Playwright и axe-core.

## Запуск

Требуется Node.js 22.12+. Для сборки на GitHub Pages используется Node.js 24.

```sh
npm ci
npm run dev
```

Адрес разработки: http://127.0.0.1:5173.

```sh
npm run build
npm run preview
```

Сборка создаёт `dist/`: готовые HTML-файлы всех страниц, локальные изображения, шрифты и JS/CSS с хешами. Для публикации нужно содержимое `dist/`, исходный `index.html` без сборки не предназначен для хостинга.

Сайт использует обычные ссылки и отдельный HTML для каждого URL. Это сохраняет прямое открытие и перезагрузку вложенных страниц на статическом хостинге. Содержимое и навигация доступны без JavaScript; диалог, мобильное меню и увеличенный текст требуют JavaScript. Неизвестные адреса показывают страницу 404. В реестре сохранены также исторические адреса `/new/.../` и `/project/all-projects/.../`, включая регистр букв.

Компоненты отображают редакционный текст через JSX. Данные публичных страниц типизированы и хранятся отдельно от отображения.

## Документы и реквизиты фонда

В библиотеке `/about/constituent-the-documents/` доступны документы из `public/documents/` в PDF и DOCX. Оферта, политика обработки персональных данных, согласие и политика безопасности платежей также открываются как обычные HTML-страницы `/documents/offer/`, `/documents/privacy/`, `/documents/consent/`, `/documents/payment-security/`. Страницы и скачивание работают без JavaScript.

- `src/constants/legal.ts` — реквизиты фонда, маршруты документов и имена файлов.
- `src/constants/legal-content.json` — полный текст документов для чтения на сайте, включая оба приложения к оферте.
- `src/configs/site.ts` — почта и телефон фонда.
- `public/documents/` — пять комплектов PDF и Word; `foundation-details` содержит карточку фонда.
- `public/images/payments/` — логотипы из предоставленного шаблона Best2Pay.

При замене редакции синхронно обновляйте файл PDF, файл DOCX и текст HTML-страницы. В предоставленных оферте и политике персональных данных не заполнены номера и даты протоколов Совета фонда: это отмечено на страницах (`approvalPending`). После получения реквизитов решения обновите документы и сведения об утверждении.

Форма обсуждения пожертвования открывает письмо директору фонда. Размещение платёжной политики не подключает интернет-эквайринг.

## Рабочие панели фонда

- `/admin/` — учётные записи, роли и активность сотрудников. Доступ по роли `admin`.
- `/moderator/` — новости, события, проекты, фотографии и документы. Доступ по ролям `moderator` и `admin`.

После входа API устанавливает HttpOnly cookie `session`. При перезагрузке вкладки панель восстанавливает профиль через `GET /me`. Смена пароля завершает сессию на сервере. Кнопка «Выйти» закрывает панель в текущей вкладке. Для отзыва сессии по этой кнопке нужен маршрут выхода в API.

Для локального запуска скопируйте `.env.example` в `.env.local`. Можно указать `VITE_API_BASE_URL=/api/v1` и задать `STAFF_API_PROXY_TARGET` с адресом действующего API до пути `/api/v1`. Такой прокси доступен в режиме разработки Vite.

### Вход на GitHub Pages

1. Для входа нужен постоянно доступный HTTPS API. Текущая cookie `SameSite=Lax` требует, чтобы сайт и API были на одном сайте в терминах браузера, например `fund.example.org` и `api.example.org`. Для разных origin сервер разрешает конкретный origin через CORS, возвращает `Access-Control-Allow-Credentials: true` и поддерживает `OPTIONS`, методы `GET`, `POST`, `PATCH`, `PUT`, `DELETE` и заголовок `Content-Type`. Для стандартного адреса Pages `https://valder111.github.io` и API на стороннем домене нужно согласовать с владельцем API вариант размещения.
2. В репозитории клиента откройте **Settings → Secrets and variables → Actions → Variables** и добавьте `VITE_API_BASE_URL`. Значение должно быть полным публичным URL с окончанием `/api/v1`, например `https://api.example.org/api/v1`. GitHub Actions передаёт этот адрес в сборку.
3. Запустите **Actions → Deploy website → Run workflow** на ветке с актуальным workflow. После публикации войдите в панель с учётной записью рабочего API фонда.

В сборку попадает только адрес API. Пароли и токены остаются за пределами сборки. Если переменная пуста, Pages публикует сайт, а форма входа остаётся недоступной.

Главная, новости, события, проекты и документы показывают опубликованные материалы API после загрузки страницы. Карточки ведут на отдельные страницы материалов. Редакционные материалы из сборки доступны независимо от API.

Редакция сохраняет формы через 7 секунд после последней правки и при переходе из формы. Новые события и проекты до публикации хранятся в браузере. Незавершённые формы можно восстановить в том же браузере, снова открыв форму. Материалы появляются на сайте после нажатия «Опубликовать». Для дальнейшего редактирования доступны поля, которые поддерживает действующий API.

Браузерные проверки редакции в `tests/staff-content.spec.ts` запускаются на сборке с `VITE_API_BASE_URL=/api/v1` и подменяют запросы API тестовыми ответами.

## Дизайн и интерактивность

Сохранены палитра, композиция, тексты, адаптивные состояния, изображения, локальные шрифты и GSAP-анимации исходного сайта. Для читаемости немного усилен контраст нумерации секций, второстепенного текста и оранжевой карточки. Tailwind отвечает за утилиты и общие стили; особенности макета оформлены в слое `components`, чтобы генератор shadcn мог безопасно добавлять компоненты.

Диалог поддерживает закрытие по Escape, кнопке и фону, удерживает фокус внутри и возвращает его на кнопку открытия. Мобильное меню поддерживает Escape. Настройка увеличенного текста сохраняется локально; при недоступном хранилище работает в пределах страницы. Анимации учитывают `prefers-reduced-motion` и отключаются в режиме увеличенного текста.

## Проверки

Чтобы включить локальные проверки перед коммитом после клонирования, выполните в каталоге проекта:

```sh
git config --local core.hooksPath .githooks
```

На Linux и macOS дайте файлу хука право на исполнение командой `chmod +x .githooks/pre-commit`. Хук запускает ESLint и проверку типов TypeScript. Если проверка завершается ошибкой, Git останавливает коммит.

```sh
npm run typecheck
npm run lint
npm run format:check
npm run build
npm run test:e2e
# lint + build + браузерные проверки:
npm run check
```

По умолчанию браузерные тесты используют установленный Google Chrome. Для Chromium Playwright:

```sh
npx playwright install chromium
```

Затем установите переменную `PLAYWRIGHT_CHANNEL=chromium` перед `npm run test:e2e`. В PowerShell: `$env:PLAYWRIGHT_CHANNEL = 'chromium'`.

Проверки покрывают все 44 адреса и исходные тексты, HTML без JavaScript, вложенные адреса и перезагрузку, локальные ресурсы, внутренние ссылки, диалог и фокус, мобильное меню, FAQ, сохранение настройки текста, ширины 360–1440 px, аудит axe и запуск анимаций. Автоматические проверки не заменяют приёмку содержания и доступности заказчиком.

## Размещение

По умолчанию базовый путь — `/`, что подходит для `https://<user>.github.io/` и собственного домена. Для сайта проекта скопируйте `.env.example` в `.env` и задайте `BASE_PATH=/repository/` до сборки. Путь должен начинаться и заканчиваться `/`.

Публикуйте только содержимое `dist/`. Workflow `.github/workflows/deploy.yml` публикует сайт после отправки изменений в `main`; также доступен ручной запуск:

1. После своей отправки изменений выберите в Settings → Pages источник **GitHub Actions**.
2. Путь определяется автоматически по настройкам GitHub Pages. Для этого репозитория стандартный адрес — `https://valder111.github.io/ZGU-endowment-client/`. Для публикации на `fund.polaruniversity.ru` задайте этот адрес в **Settings → Pages → Custom domain** и настройте DNS у владельца зоны `polaruniversity.ru`. Сборка сайта на собственном домене использует путь `/`. При необходимости путь можно переопределить переменной репозитория `BASE_PATH`.
3. Откройте Actions → Deploy website → Run workflow.

Workflow собирает сайт с фактическим путём Pages и публикует `dist/`. Команда `npm run test:pages` локально проверяет уже собранный `dist/`.

Сборка добавляет `.nojekyll` и `404.html`; rewrite всех URL на главную не требуется. Официальная инструкция по размещению: [Vite — GitHub Pages](https://vite.dev/guide/static-deploy#github-pages).

## Что требует отдельного согласования

Исходник обозначен как концепция: сохранены `noindex,nofollow`, пометка «ПРОЕКТ САЙТА», заглушка пожертвования и незаполненные разделы документов/отчётности. Приём платежей не подключён. Перед публичным запуском заказчику необходимо утвердить материалы, реквизиты, документы, условия участия и решение об индексации. Эти данные не подменялись вымышленными.

Проект перенесён в репозиторий `ZGU-endowment-client`. Существующие Git-история и `origin` сохранены. Стартовый шаблон репозитория помещён в локальный архив `.migration/target-template-before-transfer-*`. Коммиты и отправка изменений не выполнялись.

Подробные результаты локальной проверки: [docs/VERIFICATION.md](docs/VERIFICATION.md).
